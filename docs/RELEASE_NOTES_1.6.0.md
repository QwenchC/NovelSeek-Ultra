# NovelSeek Ultra 1.6.0 更新说明

1.6.0 将项目入口升级为创作工作台，把章节规划、场景写作、待审稿和作者修订接入同一流程。显示版本为 `1.6.0`，内部版本号为 `15`。本文对应当前开发实现，不表示已经完成 GitHub 发布或真机验收。

## 创作工作台与统一写作流程

- 从短篇或长篇列表打开项目，默认进入工作台，集中显示下一章、待审核候选稿、场景任务和章节列表。原有分卷、弧线及项目管理界面保留在“项目结构”入口。
- “写作偏好”可选择快速写作、场景写作、精修审稿，设置叙述视角、文风节奏、禁用表达和认可的正文样例。
- 编辑器、传统智能体和双智能体共用章节写作服务。智能体结构仍可在设置中选择。
- “规划场景”生成可编辑的场景计划。每章支持 1–8 场，可调整顺序、视角、时间地点、目标、冲突、转折、入场与结束状态，以及必需事件和禁止事件。
- 逐场生成并持久化已完成场景；工作台可暂停、取消或恢复任务。恢复会核对原始章节、正文和生成上下文，来源变化时提示重新规划，完成的场景草稿仍保留。
- 已完成场景可在任务卡中单独预览；即使来源已过期，也能查看未采用的旧草稿。预览仅阅读，不会覆盖当前正文。
- 精修审稿模式在场景写作完成后执行一轮 AI 审稿，展示事实冲突、人物知情越界、遗漏事件、文风与节奏等意见，并关联正文引用。意见用于作者审核，不自动改写正式正文。

## 在原处审核与按意见修订

工作台待审核卡、编辑器候选稿入口和智能体会话内“审核候选稿”使用同一审核工作台：

- 完整候选正文按片段展示，支持长章阅读。
- “修改对比”按段落锚点显示原文与候选稿，可选择全部采用、保留原文或仅采用所选修改。重复或移动段落会合并显示为较大的修改块。
- “提出修改意见”可要求保留开场、改写结尾、调整人物知情等，生成新的修订候选，记录作者意见与修订历史。
- 拒绝或采用均针对确定的生成记录和候选稿；来源或候选在审核期间变化时拒绝陈旧操作。正式正文只有明确采用后才改变。

## 故事卡片、阶段模型与请求额度

- 工作台“故事卡片”区分作者设定、未来计划、已发生事实、人物认知和伏笔，可关联来源章节、知情人物及计划回收章节。
- 已发生事实须有来源章节；卡片绑定来源正文摘要。来源修改或删除后，失效卡片退出生成上下文，核对保存后再绑定当前来源。
- 场景生成按章节时序选择卡片；未来事件、未验证计划和作者知道的秘密不直接当作人物已知事实。必需卡片超出预算时明确报错，避免静默删掉硬约束。
- “写作偏好”可分别指定规划、正文、审稿和资料提取使用的模型 Profile；未指定时使用全局模型。
- 单次任务请求上限可设为 1–64，规划、生成、续写、协议重试及审稿计入请求预算。任务和待审稿展示请求次数与输入/输出 Tokens；供应商未返回 usage 时显示未知。
- 单独点击“规划场景”产生独立规划统计，正文任务的限额从该任务开始计算；作者意见修订与失败重试计入对应候选任务额度。

## 智能体精确读取长资料

- `read_chapter` 和 `get_outline` 支持 `offset/limit`，兼容 `start/length`，不再只返回章节前 8,000 字或大纲前 2,500 字。
- 返回完整资料长度、当前范围、`nextOffset` 与 `sourceHash`，可逐页读到末尾；单页最多 12,000 UTF-16 字符，并保护 emoji 等 Unicode 边界。
- 可在本章或大纲内用 `query` 查找文字；新增 `search_project_text`，跨大纲和正文搜索，返回来源章节、命中偏移及上下文，每页最多 30 条。
- 结构化读取中的正文引语按资料处理，不会因为包含“无法审阅”等文字而被误记为工具执行失败。
- 延续 1.5.6 的严格 JSON 输出、长大纲和角色导入分批、按截断原因有限续写、完整成功后提交等处理。新场景流程同样不将截断稿直接采用为正式正文。

## 书稿导入与出版导出

- 工作台“导入书稿”支持 UTF-8 的 TXT、MD、Markdown，包括 UTF-8 BOM。识别中文章回标题、英文 Chapter 标题和 Markdown 标题，先预览拆章结果，再确认追加到当前项目。
- 导入不调用 AI，保留现有章节。单次最多 10 MiB、500 万字符、2,000 章；非 UTF-8、空白或超限输入会给出错误提示。
- 项目“导出”新增 EPUB 3 和 DOCX，包含书名、作者、章标题和完整文字正文，可选大纲及优先正文/草稿。EPUB 含目录导航；DOCX 含标题样式和中文正文段落。
- TXT、Markdown、PDF 保留。封面、推文图和段落插图选项仍适用于 PDF；EPUB/DOCX 当前输出文字内容。

## 完整备份与兼容

- 设置“数据备份 / 恢复”默认导出 ZIP，也可选择 PC 兼容 JSON。导入自动识别 ZIP 或旧版 JSON。
- ZIP 使用独立格式版本 `1` 包装现有 `BackupBundle.version=1`，由 `manifest.json`、元数据和逐项附件组成；正文、配图、生成记录、场景计划及检查点分别拆分，每个数据项记录字节数和 SHA-256。
- 备份补齐写作偏好、故事卡片、候选稿及场景写作进度。导入先校验所有项，再进入确认；实际导入继续使用包含正文与元数据的可恢复事务。
- 拒绝未知版本、清单外项、缺失项、重复或越界路径、重叠附件目标和校验不符；限制单项、总解压、输入大小及文件项数。默认单项 64 MiB、输入/总解压各 512 MiB、最多 50,000 项。
- API Key 默认不导出；用户明确选择包含密钥时保留原有明文迁移确认。ZIP 校验用于发现损坏，不提供加密或来源认证。
- 全部恢复智能体会话和模型配置时，应在导入确认中选择“同时导入应用设置”。桌面 2.1.0 已支持 ZIP/JSON 双向互通，按项目扩展保留回传；操作与恢复边界见 [两端数据交换说明](DATA_INTERCHANGE.md)。Android 完整恢复仍应保留本端原始备份。
- 导入会话保留计划、审核身份与历史，取消源端自动恢复和自动批准权限。导入前拒绝尚未结束或等待审核的智能体；事务期间拦住旧内存写入与新命令，提交后刷新会话列表。跨端旧任务与候选不会自动执行。
- 现有本地文件存储、旧 JSON 与旧项目入口保持兼容，不要求重建作品。覆盖升级需使用与已安装版本相同签名的 APK。
