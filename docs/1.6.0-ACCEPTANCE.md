## 本轮新增：桌面 2.1.0 双向互通

交换流程见 [两端数据交换说明](DATA_INTERCHANGE.md)，以下检查仍需在隔离数据副本与设备执行。

- [ ] 两端各准备含不同草稿/定稿、插图、角色、工作台偏好、故事卡、场景进度及会话的样本，ZIP 导入并回传。预期：章节归属、顺序、弧线、正文与图片完整；手动交换不自动合并同时编辑。
- [ ] Android 勾选“同时导入应用设置”恢复会话；桌面保持本机设置选项不勾选。预期：手机会话可见，桌面模型连接未被手机设置覆盖；没有导出的密钥仍需手动配置。
- [ ] 在 Android 智能体运行或等待审核时确认导入。预期：拒绝导入，提示先停止并等待任务结束；导入开始后不能启动新任务或用旧内存会话覆盖新数据，完成后会话列表及时刷新。
- [ ] 导入带旧自动恢复或自动批准权限的会话。预期：保留历史身份，不自动启动动作，不继承自动批准；跨端旧候选只读或失效，按本端资料重新规划后才能生成。
- [ ] 测试副本中退出或旋转页面打断导入，再重新打开。预期：书库与会话恢复到完整提交或回滚状态，不出现重复执行、旧会话回写或持续“运行中”的假任务。
- [ ] 桌面生成插图过程中手动修改正文或另一张插图。预期：拒绝陈旧插图写入，不覆盖正文与新图片；正常生成也不把草稿替换为定稿。

## A. 旧数据升级与入口

- [ ] 在 1.5.6 准备样本并导出原始备份，记录正文、草稿、章节顺序、配图及会话状态；用同签名 1.6.0 覆盖安装，不清除应用数据。预期：可启动，版本号正确，无数据丢失或被空值覆盖。
- [ ] 分别打开长篇与短篇项目。预期：进入创作工作台，章节、待审稿、任务和数量对应实际数据；“项目结构”可进入原分卷/弧线或短篇管理界面。
- [ ] 检查旧角色、境界、容器、知识库状态、版本快照、封面、听书进度与问答。预期：旧功能仍可进入，必要重建提示不删除原文。
- [ ] 在手机竖屏、横屏和较宽屏幕检查工作台、场景编辑、审核弹窗和格式按钮。预期：按钮可触达，长内容可滚动，无横向溢出遮挡采用按钮。

## B. 两种智能体与编辑器共用章节流程

- [ ] 建立同一章节和可复现的 3 场计划，记录相同模型、写作偏好及上下文。分别从编辑器、传统智能体、双智能体生成。预期：走同一写作策略和协议，按场保存，输出都是待审候选；模型输出不要求逐字一致。
- [ ] 依次选择快速、场景、精修审稿模式。预期：快速为整章草稿；场景按计划逐场写；精修在完成后增加一轮审稿，最终都等待作者采用。
- [ ] 修改场景顺序、视角、时间地点、入场/结束状态、必需/禁止事件及目标字数，再保存生成。预期：请求使用修改后的完整计划，显示实际场景数，不静默丢失硬约束。
- [ ] 设置规划/正文/审稿/资料提取不同 Profile，并测试未指定 Profile 的情况。预期：各阶段请求对应模型，缺省沿用全局模型，错误配置在调用前或失败阶段明确提示。
- [ ] 将任务请求上限调低至不足以完成规划、写作和审稿。预期：达到上限时停止继续请求，已完成场景保留；提高额度后可在来源未变化时继续。usage 未返回时显示未知。

## C. 场景暂停、中断与来源校验

- [ ] 第一场完成、第二场流式输出时暂停，然后恢复。预期：第一场不重复生成，未完成场重新生成，原始任务/语言与正文前缀保持，正式正文不变。
- [ ] 场景运行中切后台、旋转屏幕、返回工作台。预期：可读到实际阶段和持久化进度，不建立第二个并发任务。
- [ ] 第一场完成后强杀进程，重新打开并恢复任务。预期：识别中断状态，已完成场景仍存在，恢复从未完成场开始，不空等一个已经失活的 job。
- [ ] 暂停后分别修改章节规划、正式正文、前章正文、世界观、时间线、相关人物或故事卡片，再恢复旧任务。预期：来源校验拒绝陈旧恢复，提示重新规划，旧草稿仍可查，不覆盖当前正文。
- [ ] 来源未变时只调整模型 Profile 或请求额度再恢复。预期：按支持的运行配置继续，旧任务模式和原始写作要求不被悄悄替换。
- [ ] 生成请求未完成时删除章节或取消任务，再让迟到响应返回。预期：迟到结果不能重建已删除章节、覆盖新任务或改变正式正文。

## D. 长输出、严格 JSON 与精确资料读取

- [ ] 用真实 API 生成超长大纲，并触发服务端 `finish_reason=length`。预期：按截断原因有限续写，界面显示累计结果；全部完成后才提交，续写无法安全保留截断上下文时明确失败。
- [ ] 从长大纲导入大量角色。预期：按预算分批，统一合并；中间批次失败时不写入半批角色。
- [ ] 注入带说明文字、代码围栏、根数组、字段类型错误及截断的动作/场景/审稿 JSON。预期：严格协议拒绝错误，有限纠正受请求额度约束，不执行格式错误动作或采用残缺正文。
- [ ] 使用明确不支持 JSON Object 模式的兼容端点，再使用普通参数错误端点。预期：只对明确的 `response_format/json_object` 不支持降级，其他错误不盲目重复调用。
- [ ] 让智能体读取大于 12,000 字符的章节和大纲，按 `nextOffset` 读到末尾，并读取任意指定范围。预期：范围、总长度及摘要一致，重组正文完全相同，emoji 不被切成半个字符。
- [ ] 用章内查询和 `search_project_text` 查后半章及多章重复词。预期：返回正确章节与 UTF-16 命中偏移、上下文；结果按命中序号分页，每页最多 30 条，不装载所有命中。
- [ ] 正文包含“正文为空/过少”“无法审阅”等台词，执行读取和搜索。预期：资料读取标为成功；真正的缺章、参数错误、损坏 JSON 和来源摘要冲突仍标为失败。
- [ ] 第一页读完后修改资料，用旧 `sourceHash` 继续。预期：拒绝陈旧读取并提示重新开始。

## E. 审核、部分采用与作者修订

- [ ] 从工作台、编辑器、智能体会话打开同一待审稿。预期：原处预览完整正文、修改对比和审稿意见，不要求跳到章节编辑页。
- [ ] 选择全部采用、仅部分修改、全部保留原文，并覆盖插入、删除、重复段落及段落移动。预期：采用结果等于页面所选组合，未选内容保留；没有实质变化时不重复提交。
- [ ] 输入“保留前三段，重写结尾，主角此时不知道真相”后修订。预期：新增修订候选及意见历史，旧正文仍未改变，重新对比并确认后才采用。
- [ ] 修订时断网、超时、返回截断文本或格式错误。预期：旧候选、修订历史及正式正文保持可恢复，不把失败稿替换为当前候选。
- [ ] 打开审核后，在另一入口改正式正文/章节规划/相关上下文，或让另一个操作更新该候选，再采用。预期：来源或候选 CAS 检查阻止陈旧覆盖，并显示可理解的错误。
- [ ] 快速重复点击采用、拒绝、修订，关闭弹窗后重开。预期：不会重复采用、错误解锁智能体或把旧响应显示在新候选上。
- [ ] 通过和拒绝智能体候选。预期：采用后智能体按持久化结果继续；拒绝后暂停等待新指令，运行状态不由弹窗提前伪造。

## F. 故事卡片与人物知情

- [ ] 分别建立作者设定、计划、事实、人物认知和伏笔，关联来源、知情人物及回收章节。预期：界面和请求明确区分语义，计划不直接成为事实，作者知道的秘密不直接成为角色已知。
- [ ] 修改或删除来源章，再生成后章。预期：卡片显示失效/待核对，退出生成上下文；确认当前来源并保存后才重新使用。
- [ ] 用固定情节样本检查“只有侦探知道凶手”的知情边界和指定章节的伏笔回收。预期：请求和审稿有相应约束、引用；记录真实模型是否遵守，而非仅确认协议有效。
- [ ] 让本章必需设定超过上下文预算。预期：明确报错或要求精简，不静默删除作者硬约束。

## G. 书稿导入

- [ ] 导入 UTF-8 TXT、带 BOM TXT、MD、Markdown，包含中文“第十章”、英文 Chapter 与 Markdown 标题、空行和 emoji。预期：先显示拆章预览，标题/正文完整，不调用 API。
- [ ] 取消预览，再确认另一次导入到已有章节项目。预期：取消无写入；确认只追加新章、顺序连续、现有正文不变。
- [ ] 导入非 UTF-8、空白、含 NUL 的二进制、超过 10 MiB/500 万字符/2,000 章的输入。预期：明确错误，项目保持原状。
- [ ] 导入期间注入附件写入失败或强杀，重新启动检查章节和正文。预期：事务恢复完成，不留下只有章节元数据或只有正文附件的半份导入。

## H. 出版导出

- [ ] 导出 TXT、Markdown、PDF，确认旧格式功能仍正常，PDF 的封面/推文/插图选项可用。
- [ ] 导出 EPUB，分别使用实际电子书阅读器或 EPUB 校验器打开。预期：无损坏提示，目录导航、章节顺序、书名/作者、大纲可选项和中文/emoji 正确，长章无尾部丢失。
- [ ] 导出 DOCX，使用 Microsoft Word、LibreOffice 或 WPS 打开。预期：无修复提示，标题样式、换页、空行、前导空格和完整正文正确。
- [ ] 切换正文优先/草稿、大纲包含选项，生成书名含 `<>&`、正文含引号的文件。预期：显示正确，XML 不损坏；EPUB/DOCX 为文字出版包。
- [ ] 在系统文件选择器期间旋转屏幕，再确认保存。预期：所选格式和选项保持，文件扩展名与真实内容一致；保存失败时明确报告失败。

## I. ZIP、旧 JSON 与故障回滚

- [ ] 分别导出 ZIP 和 PC JSON，再在隔离设备恢复。预期：项目、正文/草稿、配图、故事卡片、阶段偏好、候选稿、生成记录、场景计划和检查点一致；选择应用设置时也恢复模型与会话。
- [ ] 导入 1.5.6 旧 JSON。预期：已有字段正确恢复，新字段缺省处理，不要求旧文件具有场景/生成附件。
- [ ] 解包 ZIP，仅修改某个附件，保留原清单并将 `manifest.json` 保持为首项重新压缩。预期：SHA-256 校验失败，确认界面不出现，应用数据不变化。
- [ ] 使用带重复 ZIP 文件名、`../`/绝对路径/反斜杠路径、清单外文件、缺项、重叠 JSON 目标或未知版本的测试包。预期：读取阶段拒绝，不创建任何本地路径或进行导入。
- [ ] 测试超单项、总解压、输入大小和项数上限，以及高压缩比数据/超长尾部字节。预期：及时拒绝并报告限制，不越过配置最大 512 MiB，不冻结界面或耗尽内存。
- [ ] 默认导出后检索 API Key；勾选包含密钥后取消确认，再明确确认导出。预期：默认和取消路径无密钥文件；明确确认的迁移包含密钥，导入进入 Keystore，不输出到日志。
- [ ] 注入事务阶段的正文/配图/场景/生成附件写入故障和元数据提交故障，重新打开。预期：旧数据回滚或持久化恢复完成，不能出现新元数据引用丢失附件；恢复失败时保留恢复证据并报告错误。
- [ ] 读取备份 A 后立即读取 B，或读取后取消确认。预期：A 的迟到结果不覆盖 B 或重新弹出取消的预览。
