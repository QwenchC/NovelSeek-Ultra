# NovelSeek Ultra 1.6.2 更新说明

1.6.2 修复 ComfyUI 外网 HTTPS 入口的自签名证书信任问题。没有自有域名时，只要隧道提供的域名与证书匹配，就可以在 APP 核对完整证书指纹后授权连接，不需要安装系统证书。Android 显示版本为 `1.6.2`，内部版本号为 `17`；保留 1.6.1 功能、旧项目结构和与桌面 2.1.0 的 ZIP／JSON 备份兼容。本次不修改桌面端版本。

## ComfyUI 证书核对与连接

设置页新增“此服务器的证书信任”，显示当前 HTTPS 主机、端口和已授权的完整 SHA-256 指纹。点击“查看并核对服务器证书”可查看证书主体、签发者和有效期；必须将完整指纹与电脑穿透客户端实际使用的公共证书独立核对，再勾选确认并批准。网络弹窗仅展示观察到的证书，不会自动授权。

已有 HTTP 地址可点击“切换 HTTPS 并核对隧道证书”，再应用地址。自动 HTTPS 的隧道必须使用完整 `https://隧道域名:远程端口`；不要用 IP 替代域名证书。

首次配置步骤：

1. 选择 ComfyUI，填写完整 HTTPS 基址，点击“应用地址”。
2. 查看服务器证书，与电脑端公共证书逐字比对完整 SHA-256。
3. 一致且有效时，勾选已核对确认，点击“仅信任此主机和端口”。
4. 测试连接，再生成一张小图确认完整通路。

提交任务、查询进度和下载图片共用同一证书授权；证书检查和授权读取在后台执行。详细地址规则与诊断见 [ComfyUI 外网连接指南](https://github.com/QwenchC/NovelSeek-Ultra/blob/v1.6.2/docs/COMFYUI_REMOTE.md)。

## 授权安全范围

- 授权仅适用于这台设备上的指定 HTTPS 主机、有效端口和完整证书，不进入作品 ZIP／JSON 备份或 Android 系统备份，新设备需要重新核对。
- 保留域名与有效期校验。证书变化、过期或授权数据异常会拒绝连接，不会自动信任新证书。
- 支持“撤销此服务器的信任”，使旧授权版本失效并取消旧请求；生成中撤销也会阻止后续图片下载。
- 禁止 ComfyUI 请求重定向，授权不会传播到其他域名、端口或 HTTP 地址。同一来源下的代理路径仍支持。
- 不修改文本模型 API、Pollinations、系统证书或服务器的 Host／Origin 设置。

若撤销无法保存，当前进程仍阻断旧授权，并提示重试及重启可能恢复旧记录。HTTPS 证书授权保护传输并验证服务器身份，不等于访问鉴权；不要让无鉴权 ComfyUI 任意公开使用。

## 验证与安装

517 项 JVM 回归通过，Lint 0 错误、45 条警告；主 APK 与 AndroidTest APK 构建成功。新增 TLS 和本机授权测试覆盖错误指纹、域名不匹配、证书更换／过期、来源隔离、取消、旧连接撤销、失败持久化与备份隔离。

Android API 36 模拟器通过真实公网入口完成 2 项运行测试，包括默认拒绝自签名、核对后连接成功、撤销后拒绝，以及一张 256×256 图片的真实提交、轮询、下载和解码。手机移动网络、已有作品覆盖升级、大图并发及后台息屏仍需实机验收，不能用模拟器结果代替。

Release 附带 `NovelSeek-Ultra-v1.6.2-debug.apk` 与 `SHA256SUMS.txt`。APK 为 Android Debug 构建，签名与此前 1.6.0、1.6.1 发布包一致。安装前导出作品备份；若提示签名冲突，不要卸载旧版强装。校验值及测试步骤见 [1.6.2 验证记录](https://github.com/QwenchC/NovelSeek-Ultra/blob/v1.6.2/docs/1.6.2-VERIFICATION.md)。
