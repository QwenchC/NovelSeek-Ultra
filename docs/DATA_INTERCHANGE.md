# NovelSeek 两端数据交换说明

Android 1.6.0 与桌面 2.1.0 通过通用备份交换小说数据。这里的互通是手动导出与导入，不是云同步、实时同步或多人合并编辑。

## 交换步骤

1. 先停止两端正在运行的智能体和写作任务，采用或拒绝待审核稿，等待任务结束，并分别备份当前数据。
2. 在来源端的设置页面导出 ZIP 备份。旧版 JSON 仍可使用；ZIP 可以校验附件损坏并拆分长正文。
3. 将文件传到另一端，在设置页面选择导入。确认校验结果、项目数与重名 ID，再执行导入。
4. 同一 ID 的项目、章节和设定采用备份中的数据；另一端的新编辑不会自动合并。确认正文、插图、故事卡和写作草稿后再继续工作。
5. 回传时重新导出最新备份，遵循相同流程。不要在两端同时修改同一项目后互相覆盖。

## 可交换内容

正文草稿与定稿、插图、封面、角色、世界观、时间线、副本与弧线、容器设定、本书写作偏好、故事卡、场景计划、场景检查点、模型用量与智能体会话随备份交换。对另一端尚未实现的按项目扩展（例如桌面候选与历史草稿）保留原始数据，便于以后回传；不保证所有未知顶层字段都能经应用导入后回传。

本地检索索引等派生数据不是跨端共享数据库；导入后根据需要在本机重新建立索引。两端模型/API配置属于各自设备，桌面默认保持本机设置。没有随备份导出的密钥需在目的端自行配置。

Android 若要恢复智能体会话，需勾选“同时导入应用设置”；从 Android 备份导入时，这也会合并源端模型设置，请先备份本机配置。桌面模型设置单独保存在 pcSettings，手机不会把它们当作手机模型配置。桌面会话默认随书稿导入，不必勾选桌面设置覆盖选项。

## 任务和审核边界

正在运行的场景检查点导入后转为中断，不代表目的端存在活动网络请求。外来智能体会话保留历史与计划身份，但不会自动执行以前的动作或确认。

两端生成来源摘要不同，不能凭相同章节 ID 盲目续写另一端旧任务。旧场景草稿可以只读查看；需要继续创作时，按当前资料重新规划。桌面特有候选作为扩展保存，手机不执行桌面候选的审核；手机候选记录也不会直接变成桌面的采用操作。已审核采用到正文的内容两端正常交换。

## 文件安全与恢复

ZIP 清单、附件大小、文件项数量、路径、重复项、正文指针与 SHA-256 均须校验通过。校验检测损坏，不证明备份来源可信；只导入自己的可靠备份。

默认移除已知 API 密钥。即使不带密钥，备份仍包含全部书稿和私人会话，请妥善保管。包含密钥的明文备份需要明确确认，不应公开上传 GitHub。

桌面导入书库与待恢复元数据在一个 SQLite 事务中提交，再保存元数据并确认完成。若提示元数据待恢复，不要重复导入；点击重试恢复或重启应用。Android 使用正文、状态与外部写作档案的导入恢复日志，保留自身的事务恢复方式。

## 开发者验证

两仓库各有同内容的 backup-cross-platform.json 样例。Android CrossPlatformBackupTest 写出 Java DEFLATED ZIP；桌面 interop.test.mjs 读取该真实文件并写出 PC STORED ZIP；Android 再读取 PC 文件并比较完整数据。

这些测试同时验证 Android Project/Chapter 真实反序列化和桌面章节重建字段，不等同于已在设备执行完整 Repository 恢复或已有安装的覆盖升级。

桌面测试设置 NOVELSEEK_ANDROID_BACKUP_FIXTURE 指向 Android app/build/interoperability/android-backup.zip。Android 测试设置 NOVELSEEK_PC_BACKUP_FIXTURE 指向桌面 .cache/interoperability/pc-backup.zip，并强制重跑该测试。未设置外部路径时，不应将普通本端往返测试报告为跨端验证。
